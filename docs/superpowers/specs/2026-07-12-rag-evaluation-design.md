# RAG Automated Evaluation System Design

## 1. Overview
The current system lacks an automated way to evaluate the quality of the LLM responses generated by the RAG pipelines. To ensure clinical safety and accuracy, we will build an automated LLM-as-a-judge evaluation system that measures Faithfulness, Answer Relevance, and Citation Accuracy.

## 2. Architecture
The evaluation framework will be implemented as an independent Python script to keep the main backend clean.
- **Location:** `app/backend/scripts/evaluate_rag.py`
- **Judge LLM:** Gemini (or OpenAI if configured), using the `hospital_ai.services.llm` manager.
- **Dataset:** `app/backend/tests/eval_dataset.json` containing 10-20 clinical Q&A scenarios.

## 3. Core Components

### 3.1 Evaluation Dataset (`eval_dataset.json`)
A collection of test cases with the following schema:
- `query`: The question to ask the AI.
- `role`: The user role simulating the query.
- `expected_behavior`: A string describing what the AI *should* do (e.g., "Must decline to answer due to missing evidence").
- `context_hints`: Keywords that should appear in the correct context.

### 3.2 Evaluation Metrics (LLM-as-a-judge)
The judge LLM will evaluate the chatbot's output based on three criteria, scoring each from 0.0 to 1.0:
1. **Faithfulness (Tính trung thực):** Does the answer rely *only* on the retrieved context? Are there any medical hallucinations?
2. **Answer Relevance (Đúng trọng tâm):** Does the answer directly address the user's question?
3. **Citation Accuracy (Trích dẫn):** Are citations `[E1]` used correctly to attribute claims to the retrieved context?

### 3.3 The Evaluator Script (`evaluate_rag.py`)
- Iterates over the dataset.
- Executes `ChatService.answer` using a **real LLM provider** (temporarily overriding `chat_provider` if it is set to `stub`).
- Collects the response and the exact evidence chunks retrieved.
- Constructs a prompt for the Judge LLM, containing: the original question, the retrieved context, and the generated answer.
- Parses the Judge LLM's JSON response containing the scores.
- Outputs a Markdown report (e.g., `rag_evaluation_report.md`) summarizing the average scores and highlighting failures (scores < 0.8).

## 4. Integration
The script can be run locally via `python scripts/evaluate_rag.py` and is designed to be easily plugged into a CI/CD pipeline in the future.

## 5. Security & Privacy
The evaluation runs entirely on synthetic test data (Patient Alice). No real PHI is used, ensuring compliance with HIPAA standards during testing.
