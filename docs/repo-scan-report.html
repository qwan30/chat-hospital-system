SQL query enforces active patient scope (ActiveEvidenceScope). However, role-based filtering (_apply_role_filters) runs in Python memory after LIMIT :top_k. Chunks of unauthorized document types are retrieved into memory and then pruned, which may shrink the returned context below top_k.

📦 Module Scorecards & Four-Level Verdicts
1. RAG & Clinical Graph Engine
app/backend/src/hospital_ai/services/{retrieval.py, graph_rag.py, bm25.py, reranking.py} • 25,648 SLOC
Core Asset

Ownership: Core IP & domain engine.

Architecture: SQL-backed GraphRAG without external graph DB dependencies (PostgreSQL 2-hop BFS traversal). Integrates pgvector HNSW vector search, PostgreSQL BM25 (tsvector), and Reciprocal Rank Fusion (RRF).

Critical Risk: Role-based access filters operate post-SQL query, potentially starving retrieval top-k if retrieved chunks are filtered out by user role.

2. SSE Streaming & Citation Validation
app/backend/src/hospital_ai/api/routes/chat_stream.py • app/frontend/src/lib/stream-client.ts
Core Asset

Ownership: Core clinical communication channel.

Architecture: Server-Sent Events (SSE) with streaming citation matching. Client can send abort signals; stream parser validates citation IDs against retrieved evidence IDs. Emits safe refusal ("Unable to answer") when evidence is insufficient.

3. CDI V2 Document Ingestion & Revision Pipeline
app/backend/src/hospital_ai/{loaders/, services/ocr.py, workers/jobs.py, api/routes/document_revisions.py}
Core Asset

Ownership: Core document management and clinical audit trail.

Architecture: Redis/RQ asynchronous job worker with dead-letter queue. Multi-format support (PDF, DOCX, HL7, tables). Immutable upload sessions, page-by-page OCR diffing, and reviewer approval state machine.
