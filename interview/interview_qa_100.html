🚀 100 Câu Hỏi Phỏng Vấn Chuyên Sâu
Dự án: AI-Powered Hospital Knowledge Assistant

Phần 1: Kiến trúc Hệ thống & Cơ sở hạ tầng (1-10)

1. Tại sao chọn FastAPI thay vì Django/Flask?
Trade-off A: Django phù hợp web truyền thống, nhưng RAG/LLM yêu cầu xử lý I/O tốn thời gian. FastAPI hỗ trợ Asyncio Native, giúp giải phóng luồng khi gọi API LLM, xử lý hàng ngàn request SSE streaming mượt mà mà không kẹt server.
2. Tại sao chia dự án thành Backend và Frontend riêng biệt thay vì Monolith (như Jinja2)?
System Design A: Tách biệt giúp scale độc lập. Backend cần scale GPU/CPU cho OCR, Frontend cần scale RAM cho UI. Giao tiếp qua REST API/SSE đảm bảo lỏng lẻo (loose coupling).
3. Tại sao không dùng Langchain hay LlamaIndex?
Trade-off A: Langchain tạo "hộp đen" làm ẩn đi Data Flow. Trong Y tế, việc chặn dữ liệu trái phép ở tầng SQL cần sự kiểm soát 100%. Viết Native Python Code giúp dễ debug và tránh nợ kỹ thuật từ Breaking Changes của framework.
4. Kiến trúc stream SSE (Server-Sent Events) giải quyết vấn đề gì?
STAR S: Chờ LLM sinh toàn bộ văn bản mất 15s gây trải nghiệm chán nản. A: Dùng SSE đẩy từng token text về trình duyệt ngay lập tức. R: Time-To-First-Token (TTFT) giảm xuống dưới 1s.
5. Database Connection Pool được cấu hình như thế nào để tránh quá tải?
Performance A: Dùng `asyncpg` với SQLAlchemy Async. Giới hạn pool_size=20, max_overflow=10. Tránh tình trạng 1000 user vào cùng lúc làm sập bộ nhớ Postgres.
6. Sự khác biệt khi chạy mô hình trên Docker CPU so với GPU Passthrough?
Trade-off A: Chạy CPU dễ setup cho mọi máy, nhưng OCR tốn vài phút. Docker cấu hình `deploy.resources.reservations.devices` để GPU passthrough giúp Ollama/vLLM tăng Throughput token/s lên 10-20 lần.
7. Dữ liệu tĩnh (như ảnh OCR) được lưu trữ thế nào?
Storage A: Lưu ổ cứng (Volume) thay vì nhét thẳng vào Database (tránh phình to DB). DB chỉ lưu đường dẫn file.
8. API Gateway ở đây đóng vai trò gì?
System Design A: Nằm ở cổng vào, xử lý Rate Limiting, xác thực JWT token và định tuyến (Routing) request tới các service bên dưới, bảo vệ Backend khỏi bị dội bom (DDoS).
9. Nếu Bệnh viện có 10 cơ sở, kiến trúc này Scale up thế nào?
Scalability A: API chạy theo mô hình Stateless. Ta có thể bật N container Backend phía sau 1 Load Balancer (Nginx). Cache và Queue đẩy ra Redis dùng chung.
10. Bạn xử lý lỗi mất kết nối DB như thế nào?
STAR A: Cài đặt cơ chế Exponential Backoff & Retry trong cấu hình kết nối DB. Nếu sập mạng tạm thời, server sẽ thử lại 3-5 lần trước khi báo lỗi 500.

Phần 2: Database & Vector Search (11-20)

11. Tại sao dùng PostgreSQL thay vì MongoDB?
Trade-off A: Hồ sơ y tế cần tính toàn vẹn dữ liệu cực cao (ACID). Postgres đảm bảo an toàn giao dịch, hỗ trợ JOIN bảng quyền truy cập với bệnh án rất tốt so với NoSQL.
12. Lợi ích của `pgvector` so với cơ sở dữ liệu Vector Cloud (Pinecone)?
Trade-off A: Pinecone bị khóa nhà cung cấp (Vendor Lock-in) và vi phạm chuẩn HIPAA nếu đẩy dữ liệu bệnh nhân lên Cloud. `pgvector` lưu trực tiếp vector ngay cạnh text trong DB nội bộ.
13. Cấu trúc bảng Vector (Chunks) gồm những trường nào?
DB Schema A: ID, Document_ID, Text_Content, Vector_Embeddings, Page_Number, và Metadata (chứa thông tin thời gian để lọc tài liệu cũ/mới).
14. Khái niệm Indexing HNSW trong pgvector giúp ích gì?
Performance A: Thay vì rà quét (Exact K-NN) 1 triệu vector rất chậm, thuật toán Hierarchical Navigable Small World (HNSW) tạo đồ thị xấp xỉ giúp lấy kết quả mili-giây với độ chính xác >95%.
15. Nếu cấu trúc bảng thay đổi (thêm cột), bạn quản lý ra sao?
DevOps A: Dùng thư viện Alembic Migration. Tạo các script versioning cho Database, đảm bảo 3 môi trường Dev, Staging, Prod luôn đồng bộ cấu trúc mà không mất dữ liệu.
16. Cách khắc phục khi truy vấn Database quá chậm?
STAR A: Bật logging SQL, dùng lệnh EXPLAIN ANALYZE để tìm nút thắt. Đánh Index (B-Tree) cho các cột hay truy vấn như `patient_id` và `created_at`.
17. Tại sao lại dùng Soft Delete thay vì xóa thẳng dòng (DELETE FROM)?
Compliance A: Y tế không cho phép xóa sạch dấu vết. Thao tác xóa chỉ set `deleted_at = NOW()`. Các query phải có `deleted_at IS NULL` để lọc ra dữ liệu còn dùng.
18. Làm sao để update Vector khi tài liệu y tế gốc bị chỉnh sửa?
STAR A: Khi Doc thay đổi, xóa cứng các chunks vector cũ của Document ID đó, rồi băm (chunking) và embed lại tài liệu mới, insert vào DB để thay thế.
19. Model Embedding BGE-M3 có ưu điểm gì so với OpenAI text-embedding-ada?
Trade-off A: BGE-M3 là model nội bộ (Open-source), không tốn tiền API, bảo mật tuyệt đối, và đặc biệt hỗ trợ xử lý đa ngôn ngữ tốt, sinh vector nhiều độ dài.
20. Transaction quản lý thế nào trong FastAPI?
System Design A: Dùng Dependency Injection. Session DB được tạo ở đầu Request, mọi Exception xảy ra sẽ gọi `session.rollback()`, nếu OK thì tự `commit()` ở cuối luồng.

Phần 3: RAG Pipeline & Thuật Toán Tìm Kiếm (21-30)

21. Điểm mù của Vector Search trong y tế là gì?
Concept A: Kém trong việc tìm mã số chính xác (VD: ICD-10 `J01.9` hoặc mã bệnh nhân `PT123`). Vector tìm theo ngữ nghĩa chứ không khớp ký tự.
22. Hybrid Search giải quyết điểm mù Vector Search thế nào?
STAR A: Kết hợp Vector (ngữ nghĩa) và BM25 (keyword khớp mã bệnh chính xác). Trọng số tính điểm là công thức cân bằng (Alpha = 0.5), lấy top kết quả của cả 2 thuật toán gộp lại.
23. Chunking chiến lược (Text Splitting) của bạn là gì?
Algorithms A: Dùng Recursive Character Splitter với size 1000, overlap 200 token. Tránh tình trạng câu chẩn đoán "Bệnh nhân KHÔNG bị / ung thư" bị cắt đôi thành 2 mảnh khác nghĩa.
24. Context Window Limit (Giới hạn ngữ cảnh) ảnh hưởng sao đến RAG?
Trade-off A: Nếu nhét quá nhiều tài liệu (VD: 50 trang), LLM sẽ quên khúc giữa (Lost in the middle). Tôi chỉ giới hạn RAG bốc Top 5 chunks chất lượng nhất đưa vào prompt.
25. BGE-Reranker hoạt động thế nào sau Hybrid Search?
Algorithms A: Hybrid Search vớt lên 20 tài liệu thô. Reranker là mô hình Cross-Encoder, đọc lại và chấm điểm mức độ liên quan sát sao giữa [Câu hỏi] và [Từng tài liệu], lọc lấy Top 5 tinh túy nhất.
26. Graph RAG xử lý bài toán nào mà Vector RAG "bó tay"?
Concept A: Vector RAG không hiểu tính bắc cầu. Graph RAG rút trích quan hệ: `(Thuốc A) -> [Gây Dị Ứng] -> (Chất B)`. Trả lời chính xác câu hỏi "Tại sao không được tiêm thuốc này?".
27. Trong lúc OCR gặp bảng biểu phức tạp (Table), bạn xử lý sao?
STAR A: PDF text thuần không giữ được cột bảng. Dùng thư viện nhận diện layout chuyển bảng thành dạng Markdown/HTML trước khi nhúng vector để LLM vẫn hiểu cấu trúc dòng/cột.
28. Nếu bác sĩ hỏi "Gần đây bệnh nhân thế nào?", hệ thống tìm kiếm ra sao?
RAG A: Cần áp dụng Time-weighted decay trong thuật toán Search. Cộng điểm ưu tiên cho các tài liệu có `created_at` gần với hiện tại nhất.
29. Kỹ thuật Sparse Retrieval khác Dense Retrieval thế nào?
Concept A: Sparse là BM25 (vector chứa toàn số 0, chỉ đếm tần suất từ khóa). Dense là Embedding model (chứa số thập phân dày đặc biểu diễn ý nghĩa, ngữ cảnh).
30. Nhược điểm lớn nhất của RAG truyền thống là gì?
Trade-off A: Dễ bị lạc ngữ cảnh nếu câu hỏi thiếu chủ ngữ. Đó là lý do hệ thống cần đưa cả Conversation History (Lịch sử chat) vào bộ máy Search để định dạng lại câu hỏi.

Phần 4: Phân loại, Suy luận & Routing (31-40)

31. HyDE (Hypothetical Document Embeddings) tăng chất lượng RAG ra sao?
STAR A: Câu hỏi ngắn "Điều trị gãy xương" sinh ra vector tệ. Tôi gọi LLM sinh ra một câu trả lời ảo chi tiết. Dùng câu trả lời ảo đó đi tìm kiếm tài liệu thật, độ khớp (Recall) cao hơn rất nhiều.
32. Làm sao phân loại được câu hỏi y tế và câu chit-chat (chào hỏi)?
Routing A: Sử dụng Intent Router mỏng (Zero-shot Classifier hoặc RegEx). Nếu chỉ là câu "Xin chào", lập tức trả lời mẫu tĩnh, bỏ qua chuỗi RAG Database tốn kém.
33. Decompose Question (Phân rã câu hỏi) dùng khi nào?
Reasoning A: Khi câu hỏi chứa nhiều ý: "Tiểu sử bệnh này là gì và giá tiền chữa trị?". Phân rã thành 2 luồng Search song song để lấy thông tin toàn diện rồi gộp lại sinh câu trả lời.
34. Hệ thống kiểm tra cảnh báo Thuốc (CDSS) can thiệp vào luồng chat lúc nào?
System Design A: Nếu Routing phát hiện tên thuốc, nó bắn 1 luồng phụ query vào DB Y khoa CDSS để lấy cảnh báo tương tác. Cảnh báo này sẽ được nhét lên đầu của Final Prompt để LLM chú ý.
35. Pipeline `reasoning.py` tổ chức code như thế nào?
Architecture A: Áp dụng Strategy Pattern. Tùy thuộc vào Routing quyết định (Simple, Decompose, DrugCheck), ChatService sẽ gọi đúng luồng Strategy đó thực thi.
36. Nếu User yêu cầu "Tóm tắt hồ sơ bệnh án", hệ thống làm gì?
STAR A: Hệ thống nhận diện intent, kích hoạt `PATIENT_SUMMARY_SYSTEM_PROMPT`. Lấy toàn bộ chunk mới nhất của bệnh án, chạy map-reduce để sinh ra bản tóm tắt ngắn thay vì RAG thông thường.
37. Conversation History (Lịch sử hội thoại) nhúng vào prompt như thế nào?
Prompt A: Giới hạn 5 cặp hỏi-đáp gần nhất. Đưa lịch sử vào trước User Query hiện tại, giúp LLM duy trì mạch truyện mà không vượt giới hạn token.
38. Làm sao để đánh giá mô hình phân loại Intent Router có sai sót?
Evals A: Xây dựng bộ test set (100 câu hỏi y khoa, 100 câu chit-chat) chạy automation test liên tục (CI) đo tỷ lệ F1-score của router.
39. Đánh đổi (Trade-off) của thuật toán HyDE là gì?
Trade-off A: Tăng mạnh độ chính xác, nhưng làm tăng độ trễ (Latency) thêm 1-2s vì phải tốn thêm 1 lần gọi API LLM sinh câu trả lời giả định. Chỉ nên kích hoạt với câu hỏi quá mơ hồ.
40. LLM thường "Lười" đọc tài liệu ở giữa (Lost in the middle). Khắc phục sao?
Prompt A: Bằng cách sắp xếp kết quả Reranker: Đặt chunk tốt nhất ở Đầu, chunk tốt nhì ở Cuối prompt. Các chunk kém dồn vào giữa. LLM chú ý phần đầu/cuối tốt hơn.

Phần 5: Phân quyền (RBAC) & Bảo mật Y Tế (41-50)

41. Tại sao đặt `PermissionService` ở trước luồng RAG?
STAR A: Ngăn ngừa tận gốc việc "lộ dữ liệu qua AI". Chặn tài liệu trái phép bằng SQL ở DB. LLM không bao giờ nhận được dữ liệu, nên không thể bịa hay làm lộ được.
42. `active_patient_permission_exists` kiểm tra những gì?
Security A: Nó là câu SQL xác minh Bác sĩ X có quyền với Bệnh nhân Y, Quyền đó chưa hết hạn (`expires_at`), và Bác sĩ chưa bị khóa tài khoản (`deleted_at is null`).
43. Audit Trail (Log Truy vết) lưu những trường thông tin nào?
Compliance A: Lưu `trace_id`, `actor_user_id`, `patient_id`, hành động (View/Denied), địa chỉ IP, và Timestamp để sẵn sàng phục vụ điều tra nếu có khiếu nại làm lộ PHI.
44. JWT Token trong dự án lưu trữ bao nhiêu thông tin?
Trade-off A: Chỉ lưu định danh (User_ID, Role, Expiration). Không lưu mảng Patient Scopes vì nó sẽ làm Payload JWT phình to quá cỡ, quyền cụ thể sẽ được query real-time tại DB.
45. Làm sao chống kỹ thuật tấn công SQL Injection ở tầng tìm kiếm Vector?
Security A: Sử dụng ORM SQLAlchemy để tự động Parameterize (tham số hóa) mọi input của user, vô hiệu hóa các ký tự độc hại nhúng vào câu query DB.
46. Chặn tấn công DDoS tốn chi phí API LLM bằng cách nào?
System Design A: Tích hợp Middleware Rate Limiter theo `user_id`. Cài đặt tối đa 5 câu hỏi/phút. Vượt qua sẽ trả HTTP 429 Too Many Requests.
47. Chế độ Ẩn danh (Data Masking) khi gọi LLM Cloud hoạt động thế nào?
STAR A: Dùng Regex/NER nhận diện Tên thật, CMND, sdt trong văn bản, thay bằng `[PERSON_1]`. OpenAI trả kết quả về, hệ thống decode ngược `[PERSON_1]` ra tên thật trả về cho UI.
48. Đảm bảo an toàn API Keys (Secrets) như thế nào?
DevOps A: Không bao giờ hard-code trong file. Đọc từ file `.env` qua Pydantic Settings. Trên Production sẽ nạp từ Docker Secrets hoặc AWS Secrets Manager.
49. CORS Policy được setup ở Frontend/Backend thế nào?
Security A: Cấu hình FastAPI CORS Middleware chỉ chấp nhận các origins cụ thể (VD: localhost:8081). Chặn mọi request POST lạ gửi từ tên miền khác ngoài nội bộ bệnh viện.
50. Thách thức lớn nhất khi áp dụng chuẩn HIPAA (Mỹ) vào hệ thống này?
Trade-off A: Cân bằng giữa "Năng lực AI" và "Bảo mật". Cloud AI (GPT-4) thì thông minh nhưng dễ vi phạm BAA (hợp đồng chia sẻ dữ liệu). Chạy Local AI thì bảo mật 100% nhưng phải đầu tư card GPU khủng.

Phần 6: Guardrails & An Toàn AI (Chống Hallucination) (51-60)

51. Bốn lớp phòng thủ Hallucination trong kiến trúc là gì?
Architecture A: (1) Safe Refusal Prompt, (2) Code Service Validation (extract citation), (3) LLM Citation Validator, (4) Output Guardrail scanner.
52. Lớp Input Guardrail (chống Prompt Injection) hoạt động ra sao?
STAR A: Chạy thuật toán nhận diện câu lệnh thao túng (VD: "Ignore instructions"). Trả về cờ `blocked=True`. Hệ thống ngay lập tức nhả thông báo `SAFE_INJECTION_DETECTED_ANSWER`.
53. Lớp Output Guardrail kiểm duyệt chủ đề (BanTopics) thế nào?
Security A: Thư viện llm-guard quét câu text trả về. Nếu AI vô tình "khuyên bệnh nhân tự uống thuốc X" (Medical Advice), hệ thống thay thế text bằng lời từ chối an toàn để tránh kiện tụng.
54. Làm sao kiểm tra được trích dẫn của LLM là giả mạo (Fake Citation)?
STAR A: Dùng thuật toán tập hợp (Subset) ở mức Backend. Cắt Regex mọi tag `[E_ID]`. Nếu tập ID sinh ra không nằm trong tập ID tài liệu đã retrieve, chặn đứng hoàn toàn câu trả lời.
55. Citation Validator Prompt đóng vai trò gì?
Prompt A: Một luồng LLM thứ 2 chạy ngầm, đối chiếu câu text sinh ra với text gốc của tài liệu RAG. Nếu phát hiện bịa số liệu (méo mó thông tin), lập tức gán cờ INVALID.
56. Safe Refusal (Từ chối an toàn) cải thiện Trải nghiệm UX ra sao?
Trade-off A: Thà nói "Tôi không tìm thấy dữ liệu" còn hơn đoán bừa. Lời từ chối chuẩn hóa gỡ bỏ rủi ro chẩn đoán sai, giúp bác sĩ tin tưởng phần mềm là "nguồn tham khảo trung thực".
57. Nếu Output Guardrail chạy quá chậm làm đứt Streaming SSE?
Performance A: Output Guardrail được giới hạn `timeout=3s`. Nếu chạy quá lâu do nghẽn, áp dụng Fallback: Mặc định từ chối kết quả (Fail-safe) để thà an toàn còn hơn thả cửa.
58. Phương pháp đánh giá (Eval) tỷ lệ Hallucination?
Evals A: Đo đạc bằng mô hình giám khảo (LLM-as-a-judge) như Ragas. Chấm điểm Context Precision, Faithfulness (trung thành với ngữ cảnh). Nếu Faithfulness < 0.9 thì Reject model.
59. Nhiệm vụ của Disclaimer Text cuối câu trả lời?
Compliance A: Câu "Thông tin chỉ mang tính tham khảo..." được gắn cứng trong code Backend để miễn trừ trách nhiệm pháp lý. AI không bao giờ thay thế quyết định của Bác sĩ.
60. Prompt Jailbreak khác với Prompt Injection chỗ nào?
Concept A: Injection là gài mã độc để thay đổi mục tiêu (VD: Bắt hệ thống gửi spam). Jailbreak là phá rào cản đạo đức (DAN) để ép AI nói bậy bạ. Input Guardrail chặn cả hai.

Phần 7: LLM & Prompt Engineering (61-70)

61. Tại sao không viết 10 Prompt riêng cho 10 Role (Bác sĩ, Y tá, Lễ tân...)?
Trade-off A: Khó bảo trì và không đồng nhất quy tắc y khoa. Dùng 1 Unified System Prompt trung tâm, tiêm động biến `{role}` vào để LLM tự xưng hô cho linh hoạt và tiết kiệm nỗ lực code.
62. Centralized Prompt Registry là gì?
Architecture A: Gom toàn bộ chuỗi Prompt phân tán vào một folder `core/prompts/`. Dễ dàng versioning trên Git, quản lý đồng bộ và tiện lợi cho việc chạy Automation Evals hàng đêm.
63. Dynamic System Prompt (Ghi đè Runtime) hoạt động sao?
STAR A: Prompt mặc định nằm trong source code. Admin có thể sửa prompt qua API. Bản ghi đè được lưu vào DB, ghi đè lên Pydantic Settings khi server load, không cần restart server.
64. Lớp trừu tượng `LLMManager` mang lại sức mạnh gì?
Architecture A: Cung cấp Factory Pattern. Thay vì code chết thư viện OpenAI, Service chỉ tương tác với Interface. Dễ dàng đổi qua lại giữa Gemini/Ollama bằng 1 biến môi trường `.env`.
65. LLM Stub (Mock) giúp ích gì cho quy trình Test?
Testing A: LLM sinh kết quả ngẫu nhiên (non-deterministic). Chạy Unit Test dùng Stub ép LLM nhả kết quả cố định A->B. Vừa đảm bảo Test ổn định vừa không tốn tiền API OpenAI.
66. Tham số Temperature của LLM được set bao nhiêu? Vì sao?
Prompt A: Đặt ở mức 0 hoặc 0.1. Y tế cần tính Deterministic (Chính xác, khách quan), không cần LLM phải sáng tạo hay bay bổng làm sai lệch bệnh án.
67. Kỹ thuật In-Context Learning (Few-shot) có dùng không?
Prompt A: Có. Nhét 1-2 mẫu ví dụ trích dẫn chuẩn `[E1]` vào trong System Prompt để hướng dẫn model trả về đúng định dạng Format yêu cầu thay vì format tự do.
68. Bạn kiểm soát giới hạn Token (Max Tokens) đầu ra thế nào?
System Design A: Thiết lập `max_completion_tokens=500`. Tránh tình trạng LLM nói lan man không điểm dừng, gây tốn tài nguyên và tăng độ trễ (latency).
69. Cách đối phó khi LLM Cloud (Gemini) bị lỗi 503 Service Unavailable?
DevOps A: LLMManager có cấu hình Tenacity (Retry cơ chế). Thử lại 3 lần với khoảng cách thời gian tăng dần (Exponential backoff) trước khi nhả lỗi về cho Frontend.
70. Tại sao RAG không nên lưu toàn bộ hội thoại cũ (Lịch sử) vào Vector?
Trade-off A: Hội thoại chứa nhiều câu rác ("Chào", "Hi"). Lưu chung với bệnh án sẽ gây nhiễu từ khóa. Hội thoại được quản lý riêng bằng Session ID, chỉ nhét dạng chuỗi vào prompt.

Phần 8: Bất đồng bộ & Hàng Đợi (Redis / RQ Worker) (71-80)

71. Tại sao hệ thống OCR phải xử lý bằng Bất đồng bộ (Async)?
Trade-off A: Chạy OCR một file PDF y tế có thể tốn 3 phút. Nếu làm đồng bộ, HTTP Request bị treo (Hang), User mất kiên nhẫn. Bất đồng bộ giúp API nhả kết quả "202 Accepted" ngay tức thì.
72. Tại sao chọn Redis + RQ thay vì Kafka/RabbitMQ?
Trade-off A: Kafka là Over-engineering cho dự án này, yêu cầu RAM và cấu hình phức tạp. Redis siêu nhẹ, thư viện RQ (Redis Queue) tích hợp Python rất nhanh, vừa đủ để quản lý Job y tế.
73. Luồng đi của File Document qua Worker diễn ra sao?
STAR A: (1) Upload đổi DB `UPLOADED` -> (2) Push Job Redis -> (3) Worker chạy OCR đổi DB `PROCESSING` -> (4) Chạy Embedding -> (5) Cập nhật DB `INDEXED`. UI polling DB để lấy status.
74. Vai trò của Cron Job (Sweeper) trong kiến trúc Worker là gì?
Architecture A: Nếu Worker bị Crash/OOM sập ngang, DB bị kẹt ở `PROCESSING` vĩnh viễn. Cron Job quét DB 5 phút/lần, dọn rác các file kẹt quá 30p đổi thành `FAILED` để UI thông báo cho Y tá tải lại file.
75. Sự kiện (Event) lỗi PDF xử lý thế nào trong hàng đợi?
DevOps A: RQ tự đẩy Job hỏng vào Dead Letter Queue (Failed Registry). Quản trị viên có thể vào xem Traceback lỗi (VD: Mật khẩu PDF) và bấm Retry thủ công mà không cần user upload lại.
76. Nếu muốn hệ thống OCR nhanh gấp 10 lần, bạn Scale ra sao?
Scalability A: Bật thêm 10 container Worker. Các Worker này cùng kết nối chung vào 1 máy chủ Redis. Chúng tự động bốc Job phân tán để làm (Horizontal Scaling). Cực kỳ mượt mà.
77. Job Timeout được thiết lập trong Worker có ý nghĩa gì?
System Design A: Ngăn chặn 1 file PDF chứa vòng lặp vô hạn làm kẹt nguyên 1 Worker. Set `timeout=600s` (10 phút). Quá thời gian, tiến trình sẽ bị ép kill.
78. Polling (Frontend) có gây tải nặng cho Database không?
Trade-off A: Có nếu 1000 user F5 liên tục. Tối ưu bằng cách Polling cách nhau 5 giây, hoặc tiến cấp lên WebSockets/SSE báo sự kiện để Server chủ động đẩy thông báo xuống UI.
79. Lưu trữ ảnh tạm của file PDF trên Worker diễn ra sao?
Storage A: Lưu vào thư mục `temp/` của hệ điều hành. Sau khi OCR và Embed xong, phải dùng khối lệnh `finally` để chắc chắn dọn dẹp file tạm, tránh Server bị đầy ổ cứng (Disk full).
80. State Machine của Document có những trạng thái nào?
DB Schema A: Gồm 4 state tuyến tính: `UPLOADED` -> `PROCESSING` -> `INDEXED` (thành công) hoặc `FAILED` (thất bại). Thiết kế State Pattern giúp quản lý luồng khép kín an toàn.

83. Lợi ích của Zod Validation tại Frontend?
Security A: Chặn rác ngay tại máy khách. Form điền bệnh án bị sai định dạng (VD nhập tuổi bằng chữ) sẽ bị cản lại ở UI, giảm thiểu lượng HTTP Request sai chuẩn dội bom lên Backend.
84. Thách thức lớn nhất khi parse cú pháp Markdown Stream từ AI?

Phần 10: Vận Hành, Kiểm Thử & CI/CD (91-100)

91. Tại sao dùng Playwright thay vì Selenium cho E2E Testing?
Trade-off A: Playwright hỗ trợ test Async/Streaming tốt hơn rất nhiều. Chức năng `expect().toContainText()` tự động chờ Auto-wait cho đến khi AI stream xong toàn bộ chữ, không cần dùng `sleep(15)` thủ công tốn thời gian.
92. Unit Test cho RAG bị ngẫu nhiên (Flaky test). Xử lý thế nào?
STAR A: Không gọi API thật trong Unit Test. Tiêm `StubLLM` vào Service thông qua Dependency Injection. Dù gọi 100 lần nó vẫn nhả về cùng một câu A, giúp test CI/CD xanh tuyệt đối.
93. Docker Compose cấu trúc mạng (Network) nội bộ ra sao?
DevOps A: Đóng kín Postgres và Redis trong `internal_net`. Chỉ mở port Backend (8000) và Frontend (8081) ra ngoài `public_net`. Ngăn chặn Hacker rà quét port Database trực tiếp.
94. Bạn giám sát (Monitor) lỗi trên Production bằng công cụ gì?
MLOps A: Chèn Middleware bắt exception đẩy log lên Sentry. Theo dõi Latency, % Citation rate trên Grafana/Prometheus từ hệ thống `MetricsService` của dự án.
95. Nếu lên Production bị sập API, Rollback như thế nào?
DevOps A: Sử dụng Docker Image tagging. Khi bản `v1.2` lỗi, đổi tag trong Compose/Kubernetes về lại `v1.1` và restart container. Giảm downtime xuống vài giây.
96. Vai trò của `pytest-asyncio` trong dự án Backend?
Testing A: Mọi API FastAPI đều là `async def`. Cần pytest-asyncio để tạo vòng lặp sự kiện (Event Loop) test các hàm gọi LLM hoặc Database async mà không bị block dead-lock.
97. Làm sao để test phân quyền (Permission) tự động?
STAR A: Viết Fixtures tự động nạp (Seeding) Bác sĩ A, Bệnh nhân B, C. Dùng `httpx` giả lập User A truy cập User C. Đo lường code trả đúng mã HTTP 403 Forbidden thay vì rò rỉ 200 OK.
98. Lợi ích của thư mục `scripts/seed_dev.py`?
DevOps A: Khi một Dev mới join dự án, chỉ cần `docker compose up` và chạy script. Nó tự bơm 10 bệnh nhân giả mạo (Fake Data) vào để code UI ngay lập tức mà không cần dựng tay dữ liệu.
99. Tại sao CI Pipeline phải quét Linter (Ruff) trước khi chạy Test?
CI/CD A: Tiết kiệm tiền CI (GitHub Actions). Quét lỗi cú pháp (Syntax/Formatting) chạy tốn 2 giây. Chạy Test RAG tốn 5 phút. Hỏng Linter thì cấm Build ngay từ vòng gửi xe.
100. Đánh giá độ thành công của Phase 1 dự án (MVP) dựa trên điều gì?
Product A: Dựa vào tỷ lệ Hallucination về 0 (Nhờ 4 lớp Guardrails), hệ thống không rò rỉ dữ liệu trái quyền, và Bác sĩ lấy được thông tin có trích dẫn tin cậy trong 30s.
